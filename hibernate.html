A practical beginner's guide

About Hibernate

Understand what it is, why Java developers use it, how it works with databases, and how it fits into a Spring application.

Start learning ↓

What is Hibernate?

Hibernate is an open-source Object-Relational Mapping (ORM) framework for Java. It connects Java objects to relational database tables, so an application can work with objects while Hibernate handles much of the database communication.

For example, a Java Customer object can correspond to a row in a customers table. Hibernate maps the object's fields to that row's columns.

In one sentence

Hibernate translates between your Java object model and relational database operations.

Why did Hibernate come about?

Relational databases store data in tables and rows, while Java programs typically represent data as objects. Before ORM tools became common, developers often had to write repetitive JDBC code to open connections, create SQL statements, bind values, run queries, read each result column, and turn the results into Java objects.

This mismatch—objects in code, tables in the database—is often called the object-relational impedance mismatch. Hibernate was created to reduce that repetitive work and let developers describe how their Java objects relate to database tables.

Before ORM: write SQL and map results yourself

String sql = "SELECT id, name FROM customers WHERE id = ?";
PreparedStatement statement = connection.prepareStatement(sql);
statement.setLong(1, customerId);
ResultSet results = statement.executeQuery();

if (results.next()) {
    Customer customer = new Customer();
    customer.setId(results.getLong("id"));
    customer.setName(results.getString("name"));
}

With Hibernate, a common lookup can instead load the mapped object for you:

Customer customer = session.find(Customer.class, customerId);
Important: Hibernate can generate SQL for many common operations, so you do not have to hand-write every query. It does not eliminate SQL entirely: you can still use JPQL/HQL, Criteria queries, or native SQL when they are a better fit.

How does Hibernate work?

You define Java entity classes and map them to database tables. Hibernate reads those mappings and uses them to generate SQL, send it to the database, and convert database results back into Java objects.

1 Map your entity

Annotations such as @Entity, @Id, and @Column describe the table and its fields.

2 Work with objects

Use Hibernate's session or Jakarta Persistence's EntityManager to find, save, update, or delete entities.

3 Hibernate talks to the database

It generates SQL, binds values, executes statements, and maps returned rows back to objects.

import jakarta.persistence.Entity;
import jakarta.persistence.Id;
import jakarta.persistence.GeneratedValue;

@Entity
public class Customer {
    @Id
    @GeneratedValue
    private Long id;
    private String name;

    protected Customer() { }
    public Customer(String name) { this.name = name; }
    public Long getId() { return id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}

A real application also configures a database connection, manages transactions, and handles schema changes intentionally. The entity needs an identifier, and JPA entities normally have a protected or public no-argument constructor.

Connect Hibernate to a database

Hibernate connects through JDBC. It needs a JDBC driver for your database and the database connection details: a JDBC URL, username, and password. The URL tells the driver which database server, port, and database name to connect to.

Example: Spring Boot with Oracle Database

Add Spring Data JPA and the Oracle JDBC driver to the project. Spring Boot's JPA starter brings in Hibernate and manages compatible dependency versions for you.

For Maven, add spring-boot-starter-data-jpa and the runtime driver com.oracle.database.jdbc:ojdbc11. Choose an Oracle JDBC driver version compatible with your Java version and Oracle Database. The Oracle driver version is not managed by every Spring Boot dependency-management setup, so specify a compatible version when needed.

Create src/main/resources/application.properties:

spring.datasource.url=jdbc:oracle:thin:@//localhost:1521/FREEPDB1
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}

# Use a migration tool such as Flyway or Liquibase in production.
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=true

Here jdbc:oracle:thin:@//localhost:1521/FREEPDB1 uses Oracle's Thin JDBC driver to connect to the Oracle Database service named FREEPDB1 on this computer at port 1521. Use the service name provided by your Oracle installation or database administrator. Set the DB_USERNAME and DB_PASSWORD environment variables before starting the application. The placeholders keep credentials out of the source file.

Security: Never commit a real database password to Git or publish it in code. Use environment variables for local development and a secret manager or protected deployment configuration in production. Use TLS and database accounts with only the permissions the application needs.

What happens when the application starts?

  1. The JDBC driver understands the database-specific URL and protocol.
  2. Spring Boot reads the URL and credentials and creates a connection pool.
  3. Hibernate uses those pooled connections to check mappings and perform database work.
  4. Your repositories or EntityManager call Hibernate, which issues SQL inside transactions.

When using Hibernate without Spring Boot, configure the same JDBC driver, URL, username, and password as Hibernate connection properties and create a SessionFactory. Choose one configuration approach for your application; Spring Boot applications typically use spring.datasource.*.

Saving and reading data

Hibernate tracks entities in a persistence context. Within a transaction, it notices changes to managed entities and synchronizes them with the database when the transaction commits. This means a separate SQL UPDATE is often not needed for a changed, managed object.

// Inside a Spring service method with a transaction
Customer customer = new Customer("Amina");
entityManager.persist(customer); // Insert when the transaction commits

Customer existing = entityManager.find(Customer.class, customerId);
if (existing != null) {
    existing.setName("Amina Khan"); // Tracked; Hibernate writes the change
}

In Spring applications, a service method is commonly marked @Transactional so related database operations either commit together or roll back together if an error occurs. With plain Hibernate, application code begins and commits or rolls back the transaction explicitly.

Finding data with a query

For a simple lookup by primary key, use find. For filtering, JPA offers JPQL, a query language written in terms of entity classes and their fields rather than table names and columns:

List<Customer> customers = entityManager
    .createQuery(
        "select c from Customer c where c.name = :name",
        Customer.class)
    .setParameter("name", "Amina")
    .getResultList();

Parameters keep values separate from the query text. Hibernate converts JPQL to database SQL. Native SQL is also available when needed, but queries should be parameterized rather than built by concatenating user input.

For an Oracle database, a native SQL query can use Oracle's SQL syntax and real table and column names:

List<Object[]> rows = entityManager
    .createNativeQuery(
        "SELECT CUSTOMER_ID, NAME FROM CUSTOMERS WHERE CUSTOMER_ID = :id")
    .setParameter("id", customerId)
    .getResultList();

Use JPQL when you want a query based on mapped Java entities. Use a native Oracle SQL query when you specifically need Oracle SQL features or want to query tables directly. Hibernate can generate Oracle-compatible SQL for entity operations when connected with the Oracle JDBC driver.

Entities, relationships, and schema changes

Entities can describe database relationships. For example, many orders may belong to one customer. JPA annotations such as @ManyToOne and @OneToMany represent these relationships. The database still stores them using keys and constraints.

  • Lazy loading fetches some related data only when it is accessed. It can save work, but the needed session or transaction must still be available.
  • Eager loading retrieves related data immediately. Too much eager loading can make a query unnecessarily large.
  • Cascades propagate selected operations between related entities. Configure them deliberately so saving or deleting one object does not cause unwanted changes.

Schema generation also needs care. Hibernate's ddl-auto setting controls whether it validates or changes database tables. validate checks mappings without changing the schema; update attempts changes and may be useful for experiments, but it is not a reliable production migration strategy. Production teams commonly use Flyway or Liquibase to version and review schema changes.

Common Hibernate terms

  • Entity: a Java class mapped to a database table.
  • Session / EntityManager: an interface for working with entities and persistence operations.
  • Transaction: a group of operations committed or rolled back together.
  • Persistence context: the set of managed entities Hibernate tracks during a unit of work.
  • Dialect: database-specific SQL behavior. Hibernate can generally determine the dialect from the JDBC connection.

Hibernate and Spring: what came first?

Hibernate existed before the Spring Framework. It began in 2001, while Spring's first public release followed in 2003. Hibernate did not arrive as a feature of Spring; it is a separate persistence framework that Spring applications can integrate with.

Spring helps create and connect application components and manage concerns such as dependency injection and transactions. Hibernate handles object-relational persistence. In a Spring application, Spring Data JPA is often used as a convenient repository layer, and Hibernate is frequently the JPA provider underneath it.

Spring Data JPA is not Hibernate. JPA (now Jakarta Persistence) is a standard API; Hibernate is a popular implementation of that standard. Spring Data JPA can use Hibernate behind the scenes.

Where is Hibernate used?

Hibernate is used in Java applications that need to persist and retrieve data from relational databases. Typical examples include:

  • Web applications and REST APIs that store customers, orders, products, or accounts.
  • Enterprise systems with many related data entities and transactional workflows.
  • Spring Boot applications using Spring Data JPA with Hibernate as the persistence provider.
  • Batch jobs and backend services that read or update relational data.

What Hibernate can help with

  • Mapping Java classes and relationships to tables and foreign keys.
  • Generating SQL for common create, read, update, and delete operations.
  • Managing entity state and coordinating database work within transactions.
  • Reducing repetitive low-level JDBC and result-set mapping code.

What to use carefully

Hibernate does not make database design or performance automatic. Developers still need to understand SQL, indexes, transactions, query plans, and schema changes. Watch for issues such as loading too much data, the N+1 query problem, or keeping a database session open longer than necessary. For complex reports or highly specialized queries, explicit SQL may be the clearest choice.
