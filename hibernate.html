About Hibernate

Understand what it is, why Java developers use it, how it works with databases, and how it fits into a Spring application.

What is Hibernate?

Hibernate is an open-source Object-Relational Mapping (ORM) framework for Java. It helps map Java objects to relational database tables and handles SQL generation, object persistence, and query execution.

Instead of writing lots of repetitive JDBC code, you work with Java entities, and Hibernate takes care of the database communication.

In one sentence

Hibernate bridges the gap between Java objects and relational database tables.

Why did Hibernate come about?

Java applications work with objects, while databases store data in rows and columns. This difference is called the object-relational mismatch. Hibernate was created to reduce the tedious work of manually converting Java objects into SQL and back again.

Before ORM, developers often wrote code like JDBC statements, result-set mapping, and manual SQL handling. Hibernate simplifies that by letting developers focus on the domain model.

Example: manual JDBC vs Hibernate

String sql = "SELECT id, name FROM customers WHERE id = ?";
PreparedStatement stmt = connection.prepareStatement(sql);
stmt.setLong(1, customerId);
ResultSet rs = stmt.executeQuery();

if (rs.next()) {
    Customer customer = new Customer();
    customer.setId(rs.getLong("id"));
    customer.setName(rs.getString("name"));
}

With Hibernate, the same operation can be much simpler:

Customer customer = session.find(Customer.class, customerId);

How does Hibernate work?

Hibernate uses metadata, usually annotations or XML mappings, to know how Java classes correspond to database tables. It then uses that metadata to generate SQL statements automatically.

1 Define entity

Create a Java class and map it to a table using annotations such as @Entity, @Id, and @Column.

2 Use session

Open a Hibernate session or use EntityManager to save, update, delete, or load objects.

3 Generate SQL

Hibernate creates the SQL, executes it, and converts rows back into Java objects.

import jakarta.persistence.Entity;
import jakarta.persistence.Id;
import jakarta.persistence.GeneratedValue;

@Entity
public class Customer {
    @Id
    @GeneratedValue
    private Long id;

    private String name;

    protected Customer() {}

    public Customer(String name) {
        this.name = name;
    }

    public Long getId() { return id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}

Core Hibernate concepts

  • Entity: a Java class mapped to a database table.
  • Session: the main interface for interacting with Hibernate and managing persistence operations.
  • Transaction: a unit of work that is committed or rolled back as one logical action.
  • Persistence context: the first-level cache where Hibernate tracks managed entities.
  • Relationship mapping: associations such as @OneToMany, @ManyToOne, and @ManyToMany.
  • Dialect: database-specific SQL behavior, such as Oracle, MySQL, PostgreSQL, or SQL Server.

Hibernate vs JDBC

Approach What you usually write What Hibernate/JPA does
JDBC SQL, connection code, prepared statements, result-set mapping Nothing automatically; you handle everything manually
Hibernate / JPA Entity classes and persistence calls Generates SQL and maps results to Java objects
Spring Data JPA + Hibernate Repositories, entity mappings, custom queries when needed Spring manages wiring while Hibernate handles persistence

Hibernate and Spring

Hibernate existed before Spring. It is a separate persistence framework, while Spring is a broader application framework. In a Spring application, Spring often manages dependency injection and transaction boundaries, while Hibernate handles persistence.

In Spring Boot projects, developers commonly use Spring Data JPA and Hibernate underneath it. JPA is the standard API, and Hibernate is one of its most popular implementations.

Important: Spring Data JPA is not the same as Hibernate. It is a higher-level abstraction that often uses Hibernate behind the scenes.

How Hibernate connects to a database

Hibernate uses JDBC to connect to a database. You need a database driver, a JDBC URL, a username, and a password. The database URL tells Hibernate which database server and database to connect to.

In a Spring Boot project, this configuration usually goes in application.properties or application.yml.

spring.datasource.url=jdbc:oracle:thin:@localhost:1521:orcl
spring.datasource.username=system
spring.datasource.password=secret
spring.jpa.database-platform=org.hibernate.dialect.OracleDialect
spring.jpa.hibernate.ddl-auto=update

In real applications, it is also important to manage transactions carefully and choose a schema strategy that fits your environment.

Advantages of Hibernate

  • Reduces repetitive JDBC and SQL boilerplate.
  • Improves productivity when working with Java objects and relational data.
  • Supports object relationships such as one-to-many and many-to-many.
  • Helps with transaction management and persistence lifecycle.
  • Works well with Spring Boot, Jakarta EE, and enterprise Java apps.

Things to watch out for

  • Lazy loading can cause unexpected database access if the session is closed.
  • Bad entity design can lead to N+1 query problems.
  • Hibernate does not replace SQL knowledge; performance tuning still matters.
  • Schema generation settings such as ddl-auto must be used carefully in production.

Where is Hibernate used?

Hibernate is used in Java applications that need to save and retrieve data from relational databases. Typical uses include:

  • Web applications and REST APIs
  • Enterprise systems with complex data models
  • Spring Boot services
  • Backend systems storing customers, orders, transactions, and reports
