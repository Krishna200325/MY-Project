What is Spring Core?

Spring Core is the foundation of the Spring Framework. It provides the core container that manages Java objects, their lifecycle, and their dependencies.

In simple terms, Spring Core helps you build applications where objects are created, wired together, and managed by the framework instead of manually by your code.

In one sentence

Spring Core is the part of Spring that manages objects and their dependencies.

Why do we need Spring Core?

In traditional Java applications, classes often create their own dependencies manually. This makes code harder to test, harder to change, and more tightly coupled.

Spring Core solves this with Dependency Injection (DI) and Inversion of Control (IoC). Instead of creating objects directly, you define them as beans and let Spring wire them for you.

Without Spring Core

public class OrderService {
    private final EmailService emailService = new EmailService();
}

The class creates its dependency itself, which makes it difficult to replace or test.

With Spring Core

public class OrderService {
    private final EmailService emailService;

    public OrderService(EmailService emailService) {
        this.emailService = emailService;
    }
}

Here, the dependency is provided from outside, which is the idea behind dependency injection.

Inversion of Control and Dependency Injection

Inversion of Control (IoC) means that control of object creation and wiring is shifted away from your code and into a container.

Dependency Injection (DI) is the mechanism used to provide dependencies to an object. Spring injects objects through constructors, setters, or fields.

1 Define a bean

Mark a class as a Spring-managed bean with annotations like @Component.

2 Inject it

Use @Autowired or constructor injection to supply the dependency.

3 Spring manages it

The container creates and wires the objects for you.

@Component
public class EmailService {
    public void send() {
        System.out.println("Email sent");
    }
}

@Component
public class OrderService {
    private final EmailService emailService;

    public OrderService(EmailService emailService) {
        this.emailService = emailService;
    }
}

Beans and ApplicationContext

In Spring, a bean is a Java object managed by the Spring container. The container is responsible for creating, configuring, and destroying bean instances.

The most common container is the ApplicationContext. It loads bean definitions, configures them, and makes them available to the application.

  • Bean Factory: base container, basic support for bean instantiation.
  • ApplicationContext: more advanced container with enterprise features.
  • Bean scope: beans can be singleton, prototype, request, session, etc.
Important: In most Spring applications, the default bean scope is singleton, which means one instance is shared by the application context.

How Spring is configured

Spring can be configured in several ways. The most common methods are Java configuration and annotation-based configuration.

Annotation-based configuration

@Configuration
@ComponentScan("com.example")
public class AppConfig {
}

XML-based configuration

<beans>
    <bean id="emailService" class="com.example.EmailService" />
    <bean id="orderService" class="com.example.OrderService">
        <constructor-arg ref="emailService" />
    </bean>
</beans>

Modern Spring applications usually use annotations and Java configuration instead of XML.

Bean lifecycle

Spring creates beans, initializes them, and destroys them according to the application lifecycle. You can hook into these phases using lifecycle callbacks.

  • Creation: Spring instantiates the bean.
  • Initialization: Spring calls init methods if configured.
  • Use: the bean is used in the application.
  • Destruction: Spring cleans up when the container shuts down.
@Component
public class MyBean {
    @PostConstruct
    public void init() {
        System.out.println("Bean initialized");
    }

    @PreDestroy
    public void cleanup() {
        System.out.println("Bean destroyed");
    }
}

Advantages of Spring Core

  • Loose coupling between classes.
  • Easier testing with mock dependencies.
  • Cleaner architecture and better code organization.
  • Centralized configuration and bean management.
  • Works well with Spring Boot and enterprise Java apps.

Things to remember

Spring Core makes your application more manageable, but it does not remove the need to understand object design, dependencies, and application architecture. You still need good design decisions and careful configuration.

Where is Spring Core used?

Spring Core is used in almost every Spring-based Java application. It is common in:

  • REST APIs
  • Web applications
  • Microservices
  • Enterprise backend systems
  • Spring Boot applications
