Spring JDBC

Learn how Spring simplifies direct database access with JdbcTemplate, prepared statements, row mapping, and transactions.

What is Spring JDBC?

Spring JDBC is a module in the Spring Framework that makes it easier to work with relational databases using JDBC. It removes repetitive tasks such as opening and closing connections, handling exceptions, and managing statements.

You still write SQL and decide how rows map to Java objects, giving you more direct control than an ORM.

In one sentence

Spring JDBC simplifies JDBC boilerplate while letting you write and control SQL directly.

Why use Spring JDBC?

Plain JDBC is powerful, but each operation typically repeats connection management, statement handling, result processing, and exception cleanup. Spring's JdbcTemplate handles that infrastructure so your code can focus on SQL and application logic.

  • Executes SQL and manages JDBC resources safely.
  • Translates JDBC exceptions into Spring's consistent data-access exception hierarchy.
  • Supports parameterized queries to avoid unsafe SQL string construction.
  • Works with Spring transaction management and connection pools.

What is JdbcTemplate?

JdbcTemplate is Spring JDBC's central helper for executing SQL. It obtains connections from a configured DataSource, executes operations, processes results, and releases resources.

1 Configure a DataSource

Provide the database URL, credentials, and JDBC driver, typically through Spring Boot configuration.

2 Inject JdbcTemplate

Spring Boot configures it from the DataSource; inject it into a repository or DAO.

3 Run SQL

Use template methods for queries, updates, and inserts with bound parameters.

Example: query and map a row

This repository uses a parameterized query and a RowMapper to convert one database row into a Java object.

@Repository
public class CustomerRepository {
    private final JdbcTemplate jdbcTemplate;

    public CustomerRepository(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }

    public Optional<Customer> findById(long id) {
        String sql = "SELECT id, name FROM customers WHERE id = ?";
        List<Customer> results = jdbcTemplate.query(
            sql,
            (rs, rowNum) -> new Customer(
                rs.getLong("id"),
                rs.getString("name")
            ),
            id
        );
        return results.stream().findFirst();
    }

    public int add(String name) {
        String sql = "INSERT INTO customers (name) VALUES (?)";
        return jdbcTemplate.update(sql, name);
    }
}
Security note: bind values with ? parameters or named parameters. Do not build SQL by concatenating user input.

Queries, updates, and RowMapper

  • Query: use query when SQL returns multiple rows.
  • Query for one value: use queryForObject for a single value or row; handle the case where no row is found.
  • Insert, update, delete: use update; it returns the number of affected rows.
  • RowMapper: maps each row in a ResultSet to a domain object. Use a named mapper when mapping is reused.
  • NamedParameterJdbcTemplate: allows readable parameters such as :customerId instead of positional ?.

Transactions and configuration

Spring can manage a group of database operations as one transaction. With Spring Boot, configure a supported DataSource, then use @Transactional on a service method when several operations must succeed or roll back together.

spring.datasource.url=jdbc:postgresql://localhost:5432/shop
spring.datasource.username=app_user
spring.datasource.password=${DB_PASSWORD}

@Service
public class CustomerService {
    private final CustomerRepository customers;

    public CustomerService(CustomerRepository customers) {
        this.customers = customers;
    }

    @Transactional
    public void register(String name) {
        customers.add(name);
        // Other related database operations join this transaction.
    }
}

Keep credentials outside source control. Use environment variables or a secret manager, and use database migration tools such as Flyway or Liquibase to manage production schema changes.

Spring JDBC vs Hibernate

TopicSpring JDBCHibernate / JPA
SQLYou write and control SQL directlyOften generated from entity operations; custom queries are also supported
MappingYou map rows, for example with RowMapperEntities and relationships are mapped by the persistence provider
Good fitFocused queries, reports, and explicit SQL controlDomain models with many persisted entities and relationships
Trade-offMore manual mapping as operations growRequires understanding generated SQL, fetching, and entity lifecycle
Both approaches can be used in Spring applications. Choose based on the data model, SQL needs, and how much mapping control the application requires.

Good practices

  • Use parameter binding rather than concatenating values into SQL.
  • Keep SQL and mapping code in a repository or DAO, separate from web controllers.
  • Use transactions for related writes that must succeed or fail together.
  • Check affected-row counts when an update or delete must change a record.
  • Use connection pooling and externalized credentials for deployed applications.
  • Test repositories against the database engine and SQL behavior you deploy.

Where is Spring JDBC used?

Spring JDBC is useful in Java backends that use relational databases and need direct SQL control, including REST services, reporting queries, batch jobs, and applications with straightforward data access.

Spring JDBC manages JDBC infrastructure for you, but you remain in control of SQL and row mapping.
